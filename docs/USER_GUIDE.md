# 使用指南

本指南說明如何用一份履歷比對整份職缺清單。工作台不是逐張職缺分別啟動的分析器：履歷確認一次後，系統會自動依序處理清單中的全部職缺，之後每張卡片都用同一個入口查看結果。

## 三分鐘快速體驗

1. 開啟工作台，先確認頁面顯示的模式是「固定範例」或「真實模型」。固定範例用於體驗操作，不代表真實 AI 分析結果。
2. 按「載入合成範例」。這會載入一份展示履歷及多份合成職缺；人物、公司和經歷皆為虛構資料。
3. 在履歷區檢查資料，按「核對履歷，確認後自動開始整批比對」進入核對頁。先檢查原文及模型整理出的事實，必要時修正或刪除錯誤項目。
4. 按「確認履歷並比對全部職缺」。確認後會自動開始整批流程；一般不必再手動啟動，也不用回到每張職缺卡片逐一提取、核對或分析。
5. 回到工作台看整批進度。完成後，每張職缺卡片都提供「查看比對結果」入口。打開任一職缺，就能看該職缺的必要／加分條件、逐項判斷、理由及履歷原文引用。
6. 若結果指出缺少證據，這只代表目前履歷沒有可引用描述，不代表你沒有該能力。可在履歷區補充真實經歷或作品來源，再核對履歷並重新比對。

## 一份履歷如何連到全部職缺

工作台上方是目前選用的履歷及其補充經歷／作品來源；下方是要用這份履歷比對的職缺清單。履歷確認後，批次以啟動時的完整職缺清單為範圍。搜尋、篩選及收藏只改變清單顯示方式，不會把其他職缺排除在整批處理之外。

系統會逐一整理尚無有效條件的職缺，再將該職缺的條件與同一份已確認履歷比對。每個結果各自保留狀態和引用；某份職缺失敗不會把它說成已完成。所有卡片的結果操作相同，差別只在卡片顯示等待、處理、完成、失敗或過期狀態。

職缺條件可在比對後再核對，因此結果可能標示「AI 提取、尚未人工核對」。這代表履歷證據與目前模型整理的條件已有初步比對，並不代表使用者已確認職缺條件。要產生或接受履歷改寫，仍須先確認履歷與該職缺的核對內容，且改寫事實檢查必須通過。

## 查看證據與修正內容

- 「有證據」應附上能支持該條件的履歷來源；點引用可回到對應原文位置。
- 「缺少證據」的意思是履歷未提供可引用內容，不是判定你不具備能力。
- 「需要確認」用於平台不明、技能年資不明、重疊或矛盾等不能安全推斷的情況。
- 原文、模型整理及你修改或確認的內容會分別標示。若原文或核對版本改變，舊結果會過期，需重新啟動整批比對。
- 搜尋、篩選、收藏與最多三份職缺比較是清單功能，不會呼叫模型，也不會重新分析。

「補充經歷與作品來源」屬於履歷，不屬於職缺。只補充可據實說明的內容；核對時要指定它支持的事實。補充內容是額外來源，不會自行變成已確認的履歷事實。

## 改寫、接受與還原

在履歷及目標職缺都已確認後，選擇履歷段落和職缺產生改寫。先比對修改前後、理由及原文依據，並檢查事實檢查結果。若建議新增原文沒有的技術、年資、成果或責任程度，系統會阻擋接受；請保留原文或補充可核對的真實來源。只有你按接受後才建立履歷新版本；拒絕不會改動履歷，已接受內容也可從版本操作還原。

## 固定範例與真實模型

固定範例模式不會呼叫模型，只用預先準備的合成結果呈現介面流程。真實模型模式會把目前任務所需的履歷或職缺文字送到設定的模型供應商；請在送出前核對傳送範圍。API 金鑰只由本機伺服器讀取，不會傳給瀏覽器。

模型分析會產生外部 API 用量與費用。整批是一次操作，不代表只有一次模型請求；首次處理一份履歷及多份職缺時，請到用量頁檢查逐次紀錄。取消可能仍產生費用，重新整理只查詢既有批次，不會自動重送。

## 重新分析、取消與資料清除

- 需要更新所有職缺結果時，使用整批區的「更新全部職缺比對」。符合版本及模型設定的有效結果可沿用，修改過的資料需重新處理。
- 若單筆錯誤，先查看該職缺結果及整批錯誤說明；整批會保留已完成結果，其他職缺仍可繼續。
- 批次可取消；已完成結果保留。若本機服務重新啟動，未完成工作會標示中斷，不會自動再次付費。
- 在設定頁使用「清除求職資料」或「清除全部本機紀錄」。清除會取消進行中的工作並移除選定資料；本機 `.env`（設定檔）不會被刪除，供應商或作業系統備份也不在本機清除範圍內。

資料保存在本機設定的資料目錄，持續保留直到你主動清除。固定與真實模式會明確標示；遇到超長文字、服務失敗或未知費用時，請依畫面提示縮小內容、檢查設定或稍後手動重試，不要把未知費用當作零。

## 觀看展示影片

執行 npx tsx scripts/serve-recordings.ts（本機影片服務），開啟 http://localhost:3003。上方選擇「三分鐘展示」或「真實模型流程」，播放不會呼叫模型。兩份影片都使用合成資料並附繁體中文字幕，沒有配音。播放器至少占畫面一半，可使用字幕、全螢幕與下載；手機直向觀看桌面錄影時，可轉橫向提高文字可讀性。
