## 已完成

- Next.js（網頁全端框架）16.3.8、React（介面元件）19.3.0、TypeScript（型別檢查）嚴格模式及 SQLite（本機資料庫）。
- 貼上、合成範例、排除傳送段落、不可變原文版本、人工修正／補充引用、逐項配對、搜尋篩選收藏及最多三職缺比較。
- 三種判斷、可回原文的引用、不推算技能年資、不將行動經驗轉成網頁經驗、非職能條件排除。
- 改寫前後、逐句主張、程式及獨立模型檢查、接受／拒絕／還原、交易防重複及版本衝突。
- 固定／真實模式、串流階段、取消、有限重試、過期與錯誤狀態、重啟恢復、資料清除及遲到回應阻擋。
- 本機唯一設定檔、伺服器金鑰隔離、同源工作階段、用量與實際／未知費用。
- 模型未能解析時可自行核對原文：每項仍須有效來源，清楚標示人工內容，不算模型解析成功。

## 真實模型流程與費用

實際瀏覽器已完成 A 解析兩份文件 → 人工確認 → B 配對 → C 生成及獨立核查 → 接受 → 還原。最後一次全新流程共五次上游請求，沒有自動重試；總費用 **US$0.01857295**，瀏覽器流程 **30,373 ms**，樣本數一，沒有瀏覽器執行錯誤。此完整流程使用驗證器第五版；之後第六版清除非職能條件的模型確認問題與建議，第七版阻擋把否定 React Web 描述當成肯定經驗，均已以單元回歸驗證，未為這些規則另重送付費流程。

前一輪包含一次解析修復，共六次，費用 US$0.02361545、35,403 ms，紀錄另存歷史。未通過驗證的費用也計入，沒有把修復當免費。實際費用與耗時會隨內容及模型改變，這不是固定價格或效能保證。詳細請求用量、影片及成功畫面見 evidence/live-flow.json（真實流程）、evidence/video-live/live-flow.webm（全程錄影）。

2026-10-07 流程改為「核對一次履歷，自動比對全部職缺」。整批管理保存每份職缺的等待、處理、完成或失敗；卡片統一「查看比對結果」，職缺條件未人工確認可先配對並明示狀態，改寫仍須確認。取消、重啟、單筆失敗、版本變更及清除不復活已有整合測試。先前動態主要按鈕的首頁設計及影片是歷史版本；新流程證據見 evidence/browser/batch-home-*（固定模式）與 evidence/batch-workflow（真實整批）。
目前沒有公開網址、雲端部署、帳號、多使用者、付費、PDF（文件格式）匯入、爬蟲、自動投遞或求職平台操作，均依已確認範圍延後。資料持續保存在本機，清除不刪 .env（設定檔）或保證抹除供應商／系統備份。

ESLint（靜態檢查工具）9 的官方維護已停止。最新 10 系列與目前 Next.js 內附規則實測不相容，因此鎖定可通過檢查的 9.39.4；這是待更新的開發工具限制，沒有停用規則來掩蓋錯誤。第三方資安弱點完整稽核、獨立人類語意評審及上述未測平台尚未完成。
